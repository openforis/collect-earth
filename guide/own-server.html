Your own server

A private server is your own copy of Collect Earth Cloud: the web dashboard, the sync service Collect Earth talks to, and a database with nightly backups. Coordinators and interpreters work exactly as on cloud.collectearth.org, and nobody else, including the Collect Earth team, can see the data.

On Google Cloud

  1. Open the self-hosting guide and press Open in Cloud Shell. Tick Trust repo and confirm.
  2. Follow the panel on the right: pick or create a Google Cloud project, and check billing is on.
  3. Run bash deploy/gcp/deploy.sh, choose the region nearest your team, and confirm.
  4. Wait: the database takes 10 to 15 minutes, building the server 3 to 6 more.
  5. Write down the dashboard address and the setup code it prints. deploy.sh --show-setup-code shows the code again.

On your own servers

Build the image (docker build -t collect-earth-cloud . in collect-earth-cloud) and run it with PostgreSQL. DEPLOY.md lists every setting; the main ones:

SettingWhat it is
STORE_BACKEND=postgresKeep the data in PostgreSQL
MIGRATION_DATABASE_URLThe database owner, to create and update the tables
DATABASE_URLA less powerful role the server runs as, so each project's data stays apart
SETUP_CODEThe one-time code for the first administrator
PUBLIC_BASE_URLYour HTTPS address, used in invitation links

The server speaks plain HTTP: put HTTPS in front of it (a load balancer, nginx or Caddy). Email settings are optional, for weekly summaries and "Forgot your password?".

First steps on a new server

  1. Setup. Open the address, type the setup code, and choose the administrator's user name and password.
  2. Server settings (the Server page): leave Anyone can create an account off for a private server, so people only get accounts through invitations. Choose Who can create projects, and optionally limits, a server name, an announcement, terms of use and a contact email.
  3. Your first project: continue as in Running a cloud project. The administrator sees no project's data unless they are also a member.
  4. Forgotten passwords: Server › Accounts › Make a reset link, or, with email set up, people use Forgot your password? themselves.

For interpreters nothing changes: the invitation link carries your server's address, so they never type it.

Looking after it

  • Updating: run the same deploy.sh command again. It switches to the new version in about 5 minutes; the data stays.
  • Your own address: deploy.sh --domain cloud.example.org, then add the DNS record it prints.
  • Restoring a backup replaces all current data: download each project's data first. Test a restore once before going live.
  • Stopping all costs: delete the Google Cloud project.
